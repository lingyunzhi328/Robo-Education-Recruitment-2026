# 4.5.1 内训方案：ROS 2 与小海龟控制

作者：郑子毅。面向机协新成员，采用 Ubuntu 24.04 与 ROS 2 Jazzy。

## 选题与机器人比赛的联系

我希望加入机协后参与机器人技术开发和竞赛。计算机专业的算法、系统和调试经验，需要通过真实的数据接口与机器人结合。本课程把“写一段 Python 程序”推进到“让独立节点通过消息共同完成运动控制”，用免费的 turtlesim 仿真降低硬件门槛，给后续视觉、导航和实车开发打基础。

课程边界是节点、话题、消息、基础发布与订阅、调试以及简单闭环控制。服务与动作只做概念比较。不在第一次内训中同时展开 SLAM、Nav2、复杂机械臂运动学或深度学习训练。

## 对象与先修基础

- 20 名新成员，两人一组，共 10 组。无需机器人开发经验。
- 建议掌握 Python 变量、函数、条件和循环。课前发 20 分钟自测及补充教程。
- 对类和回调不熟悉的同学可先修改提供的模板。前两课不要求自己从零配置软件包。
- 每组一台可运行 Ubuntu 环境的电脑，建议至少 8 GB 内存和 25 GB 可用空间。课前实际试运行决定是否达标，规格只是部署建议。

## 可检查的学习目标

结课时每组应能：

1. 指认一个节点、一个话题和一种消息类型，解释发布者与订阅者的关系。
2. 用 `ros2 node list`、`ros2 topic list -t`、`ros2 topic echo` 判断通信链路是否建立。
3. 运行 Python 发布节点，让小海龟按设定速度转圈，并说明线速度与角速度如何影响轨迹。
4. 订阅位姿，在给定目标附近停止，解释阈值、速度限幅和角度误差归一化的意义。
5. 提交可复现的启动步骤、代码、至少一条失败记录和一段演示视频。

## 教学安排：3 次，每次 90 分钟

| 课时 | 时间划分 | 课堂任务与产出 |
| --- | --- | --- |
| 第 1 次：消息协作 | 10 分钟前测，20 分钟概念演示，35 分钟 CLI 实操，15 分钟故障卡，10 分钟验收 | 运行 turtlesim 和键盘控制节点，查出 `/turtle1/cmd_vel` 的类型，使用 `echo` 观察指令。每组交一张带标注的通信图。 |
| 第 2 次：Python 控制 | 10 分钟回顾，20 分钟拆解模板，35 分钟发布器实践，15 分钟半径挑战，10 分钟验收 | 修改发布周期和 `Twist`，让小海龟走圆。区分发布频率与速度，运行限时停止示例。交代码与参数表。 |
| 第 3 次：反馈与复现 | 15 分钟位姿与误差，20 分钟闭环控制演示，30 分钟两人结对练习，15 分钟交换复现，10 分钟总结 | 使用位姿订阅器和限幅 P 控制，到达目标点后发零速度。交换仓库，按 README 启动并记录卡点。 |

每组轮换“操作员”和“讲解员”，防止只有一个人敲代码。练习采用“预测轨迹、修改一处、观察消息、解释结果”的顺序。讲师演示时放大终端字体，保留命令与预期现象，避免长时间复制粘贴。

## 第一次实践的完整操作链

以下命令在已准备好的 Ubuntu 环境运行。每个新终端都要加载环境。

```bash
source /opt/ros/jazzy/setup.bash
ros2 run turtlesim turtlesim_node
```

第二个终端：

```bash
source /opt/ros/jazzy/setup.bash
ros2 node list
ros2 topic list -t
ros2 interface show geometry_msgs/msg/Twist
ros2 topic pub --rate 10 /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 1.0}, angular: {z: 1.0}}"
```

第三个终端：

```bash
source /opt/ros/jazzy/setup.bash
ros2 topic echo /turtle1/cmd_vel
ros2 topic echo /turtle1/pose
```

停止上面的持续发布器后，再主动发送零速度：

```bash
ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0}, angular: {z: 0.0}}"
```

课堂不得让键盘控制器与自动发布器同时发送速度指令。turtlesim 有指令超时机制，但迁移到实车时仍需明确的停车指令与驱动侧看门狗，不能把退出某个终端当作通用安全停机办法。

## 第三次实践的控制思路

目标 `(x_g, y_g)` 与当前位姿 `(x, y, theta)` 给出距离误差 `d=hypot(x_g-x, y_g-y)` 和方向误差 `e=atan2(sin(theta_g-theta), cos(theta_g-theta))`。当 `d<0.15` 时输出零速度。方向偏差大时先转向，方向合适时再前进，线速度与角速度均限幅。教师解释这里是教学用的点位控制，不包含避障规划，不直接用于未知真实环境。

验收目标取 `(7, 7)`，使用小海龟默认起点并确保屏幕范围足够。额外测试角度跨越 `-pi/pi`、已处于目标内、较大转向误差。教学代码将控制数学与 ROS 节点封装分开，方便在没有 ROS 的机器上先做逻辑测试。

## 实施问题与应对

| 情况 | 可执行处理 |
| --- | --- |
| 安装或下载耗时 | 课前 3 天完成环境预检，前 1 天提供答疑。当天使用准备好的电脑结对，不把整节课变成安装课。 |
| Python 类和回调难理解 | 先让学生找到“创建发布器、创建定时器、发送消息”三处，再解释对象与回调。保留填空模板和完整参考答案。 |
| 海龟不动 | 顺序查环境、节点、话题名、消息类型、是否有订阅者、是否同时有多个速度发布者。确认版本、域编号和 QoS 后再改代码。 |
| 无线网络跨组串话 | 每组使用不同 `ROS_DOMAIN_ID`，本课程默认只在组内同一台电脑通信。同步重启节点后核验节点列表。 |
| 仿真 GUI 失败 | 两人共用预检通过的环境。若全场图形环境故障，先完成命令阅读、控制逻辑单测和录屏讨论，课后补做 GUI 验收，明确记录延期。 |
| 基础差异或进度落后 | 基础组完成走圆和主动停止，进阶组完成点位控制。助教先保证所有组取得最低可演示成果。 |

## 评价与资料传承

建议评分：概念解释 20 分，发布与停止演示 30 分，闭环控制 25 分，复现文档 15 分，故障分析与结对参与 10 分。评分不是只看轨迹漂亮，还要看学生能否解释输入、输出与停机条件。

课后匿名收集“最不清楚的一点”和“遇到的第一条错误”。教师把常见问题补到 `docs/troubleshooting.md`，将修复记录放进 Git 提交。下次开课前，维护者在冻结环境里按 README 完整运行一遍，不直接照搬未经试验的网络教程。
